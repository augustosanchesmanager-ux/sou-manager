## 4. Achado — divergência entre `AGENTS.md` e a configuração real da Vercel

### 4.1 O que a documentação afirma

`AGENTS.md`, seção "Mecânica real de deploy (Vercel `smg-barber`)", afirma que o auto-deploy de produção é bloqueado pelo **Ignored Build Step**:

```bash
if [ "$VERCEL_ENV" = "production" ]; then echo "production: apenas via promote controlado"; exit 0; fi; exit 1
```

### 4.2 O que a API da Vercel devolve (leitura only, 2026-11-16)

```
projeto smg-barber (prj_M3cJ2cZosLONAt9IzumF2LwJZTSj)
commandForIgnoringBuildStep: ""
link.productionBranch:      "main"
gitProviderOptions:         createDeployments=enabled, requireVerifiedCommits=true
```

O campo existe e está **vazio**. O mecanismo descrito **não está ativo**.

### 4.3 Consequência observada

Todo merge em `main` gerou deployment `target=production` em estado `READY`:

| sha | criado em | target | state |
|---|---|---|---|
| `8b67c95` (PR #320) | 2026-11-16T05:47:10Z | production | READY |
| `6b8e463` (PR #321) | 2026-11-16T06:12:21Z | production | READY |
| `db82d2f` (PR #322) | 2026-11-16T06:14:37Z | production | READY |

### 4.4 O que de fato segura a produção

```
barber.soumanager.com -> dpl_28F64fFyr245j7rbhuYbv9snvhdw
                        (= smg-barber-phv6n9grn-…, sha 4a6406c, target production, READY)
criado em:    2026-11-15T08:12:46Z
promovido por: Deploy Production (Promote Controlado) @ 2026-11-15T08:14:36Z
```

O domínio público está **fixo por alias** num deployment específico. `main` avançou 9 commits desde a promoção e `barber.soumanager.com` não se moveu — verificado após cada merge da rodada.

**Veredito:** o invariante `MERGE ≠ DEPLOY PROD` (ADR-026) **se mantém na prática**, porém o mecanismo que o sustenta é **promote manual protegido por environment + alias fixo**, não o Ignored Build Step. A documentação descreve um mecanismo que não existe.

### 4.5 Risco residual

1. Todo merge consome build de produção e deixa um deployment `READY` apto a ser promovido.
2. O caminho de bypass continua aberto: `vercel promote` / `vercel alias` por CLI publicaria um deployment sem passar pelo workflow, pelo environment `Production` e pelo guard anti-regressão. O freio documentado não existe para ser contornado — não há freio automatizado.
3. O `AGENTS.md` já exige verificação do campo antes de assumir o bloqueio ativo; a instrução está correta, a **realidade** é que diverge.
